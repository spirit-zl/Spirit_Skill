# 输出格式与流程规范

本文件定义读书笔记的最终形态、内容标准和与原提示词文档的对应关系。

## 一、最终文档结构

```markdown
# <书名>                    ← 全篇唯一主标题＝书名本身（不加书名号「《》」、不加"读书笔记"；上传飞书后为文档标题）

## 一、本书简介              ← 每个部分一个一级章节标题（##），中文序号 + 节名
### 书籍信息                ← 部分内的第一级内容小节（###）
#### 基本信息               ← 第二级内容（####）

## 二、作者介绍              ← 依此类推；科学知识类/历史题材/人物传记共 9 个部分，想象文学类 5 个
### ……
```

- 主标题只有一个：书名本身（如 `# 缠论：缠中说禅核心炒股技术精解（第2版）`）——不加书名号、不加"读书笔记"后缀（这是思维导图/PPT 的根节点）。
- 其下**每个部分各有一个 `##` 级部分标题**（`## 一、本书简介`、`## 二、作者介绍`……按中文序号编号），让各个部分的骨架一目了然。
- **部分内内容统一从 `###` 起**：`###` 第一级、`####` 第二级，以此类推；部分内不要再出现 `##`。
- 不添加 "Q1" 之类的机械标识；层级不得跳级。

## 二、内容规范

- **完整**：每节内容必须完整生成，不缩减、不省略；某节一次写不完就分次续写同一文件，直到完整。
- **不虚构**：不编造事实、数字、来源；不确定的信息明确写"不确定/待确认"。
- **一字不改**：组装是"按文件顺序原文拼接"，不做任何增删改写（对应原文"汇总 markdown 是指原文一字不改，一字不差的 copy"）。
- **语言**：默认中文；书名、人名、术语可用原文语言加注。
- **视角**：按各节 Prompt 的要求切换（作者视角 / 编辑视角 / 历史学家视角 / 第三方专家视角）。

## 三、从手动流程到自动执行的适配

原提示词文档是为人机对话流程（逐个提问 → 手工/AI 汇总）设计的。本 skill 中由 agent
按同样的提示词自动完成，对应关系如下：

| 原文要求 | 本 skill 中的执行方式 |
|---|---|
| 按 Q1、Q2、Q3…… 的顺序，依次向大模型提问 | agent 按顺序逐节生成，每节落盘为独立文件 `parts/0N-*.md` |
| 在代码框中以 markdown 源码格式输出 | 直接写入文件，不使用代码围栏（```） |
| AI 汇总（分两次、必要时"继续"） | 生成阶段即逐节落盘，组装阶段按顺序拼接，无遗漏风险 |
| 若回答不完整，输入"继续" | 一节写不完时分次续写同一文件，直到完整 |
| 汇总"不做任何增减，只是汇总" | `assemble_note.py` 按文件顺序原文拼接 |
| 原主标题写法（"# 《书名》读书笔记"） | 主标题与飞书文档标题统一为**书名本身**（不加书名号、不加"读书笔记"后缀） |
| 层级检查（#"##"###"是否恰好是主标题） | `assemble_note.py` 组装后自动进行结构体检并输出大纲（主标题唯一、各部分标题齐整、内容层级从 `###` 起） |
| 层级不对时的调整（# 改 ##，## 改 ### 递推） | 生成时即保证：部分标题为 `##`、内容自 `###` 起；必要时用 `assemble_note.py build --demote` 统一降级兜底 |

## 四、原提示词文档"规则"部分（存档）

> 1、有几个规则，我们先约定一下，达成一致，听懂就回答"听懂"。规则如下：比如 Q1（Question1）、Q2（Question2）、Q3（Question3）；汇总 markdown 是指原文一字不改，一字不差的 copy。
>
> 2、汇总 Q1、Q2、Q3、……Q7 的 7 个 markdown 内容。要求不做任何增减，只是汇总在一次回答中，便于复制。
>
> 3、继续汇总剩余部分的 markdown 内容。要求不做任何增加或删减，只是汇总在一次回答中，便于复制。
>
> 4、如遇到层级不对的情况，请补充：首先输出默认内容: # 《反脆弱》读书笔记，然后针对以上两次汇总的全部 markdown 内容的所有层级全部改变层级，比如原来的# 改为##，原来的##改为###，以此类推。

上述规则的意图均已由本 skill 的生成与组装流程自动满足（见第三节表格）。
