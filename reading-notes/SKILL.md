# reading-notes

把一本书生成**结构化读书笔记**，并归档到**飞书云文档文件夹**。
提示词框架来自用户既有的"读书笔记提示词"文档：四类书籍、逐节生成、统一层级规范。

## 工作流总览

```
开单确认  →  逐节生成（逐节落盘）  →  组装 + 结构体检  →  归档到飞书  →  交付链接
```

工作目录：`~/.workbuddy/data/reading-notes/work/<书名>-<YYYYMMDD>/`
（`parts/` 存分节文件，`note.md` 是组装后的完整笔记。）

生成过程一气呵成：逐节推进直到全部完成，**不要在中途停下来问用户"要不要继续"**；
全部完成后一并交付。内容较长，全程按节落盘，绝不试图一次性写完所有节。

## 1. 开单确认

生成前确认三件事，缺一项先问，不要猜：

| 事项 | 说明 |
|---|---|
| 书名 + 作者 | 防同名书；书名有歧义（同名、译名不一）先与用户确认清楚 |
| 书籍类型 | 四选一，见下表；用户没明说时按书名判断并说明依据，拿不准就问 |
| 目标文件夹 | 飞书文件夹地址；本次没给且无默认时向用户索要（见「文件夹协议」） |

**四类模板：**

| 类型 | 适用 | 节数 | 模板文件 |
|---|---|---|---|
| 科学知识类 | 科学、思维、商业、心理、自我提升等知识型书籍 | Q1–Q9 | `references/prompts-science.md` |
| 想象文学类 | 小说、史诗、戏剧等虚构作品 | Q1–Q5 | `references/prompts-fiction.md` |
| 历史题材 | 历史研究、纪实、断代史、历史随笔 | Q1–Q9 | `references/prompts-history.md` |
| 人物传记 | 传记、自传、回忆录、人物评传 | Q1–Q9 | `references/prompts-biography.md` |

开单后先读：对应类型的 `prompts-*.md` + `references/conventions.md`（格式与内容规范）。

## 2. 逐节生成

按模板顺序（Q1 → Q9 或 Q1 → Q5）逐节生成，每节写完**立即落盘**为
`parts/01-本书简介.md`、`parts/02-作者介绍.md`……（两位数字前缀保证拼接顺序）。

每节要求：

- 把模板 Prompt 中的《书名》替换为实际书名（传记类同时替换"传主"），然后以该书的
  作者/内容专家视角直接产出内容；
- **每节文件以部分标题开头**：`## 一、本书简介`、`## 二、作者介绍`……（中文序号 + 节名，
  按模板顺序编号）；部分内第一级用 `###`、第二级用 `####`，以此类推；**不要出现 `#` 级标题**；
- 内容完整、不缩减、不省略；不虚构事实/数字/来源，不确定处写"不确定/待确认"；
- 一节一次写完整；写不完就分次续写同一文件，直到完整（不要输出"继续"字样）；
- 按各节 Prompt 的具体要求执行（如 Q3/Q4/Q5 的一二级标题加粗、Q4 的 10 个概念结构等）。

## 3. 组装与结构体检

```bash
S=~/.workbuddy/skills/reading-notes/scripts
W=~/.workbuddy/data/reading-notes/work/<书名>-<YYYYMMDD>
python3 "$S/assemble_note.py" build "$W/parts" -o "$W/note.md" --title "<书名>"
```

主标题一律用**书名本身**：不加书名号「《》」、不加"读书笔记"后缀（如 `--title "缠论：缠中说禅核心炒股技术精解（第2版）"`）；飞书文档标题与此保持一致。

- 脚本按文件名顺序拼接分节文件，最前面写入主标题 `# <书名>`（书名本身，不加书名号与"读书笔记"）；
- 组装后自动体检并打印报告：标题统计、大纲、错误/警告（多 H1、跳级、空节等）；
- 发现问题：修正对应 `parts/` 文件后重新组装；若整套分节层级偏高（混入 `#` 级标题），
  确认后用 `--demote` 整体降级（`#` → `##`，`##` → `###`）；
- 只体检不组装：`python3 "$S/assemble_note.py" check "$W/note.md"`。

**结构规范（组装后必须满足）**：第一行 `# <书名>`（书名本身，不加书名号与"读书笔记"）为全篇唯一主标题；
其下每个部分各有一个 `##` 级部分标题（`## 一、本书简介` 等，中文序号编号），
部分内容第一级 `###`、第二级 `####`；不添加 "Q1" 之类的机械标识；层级不跳级。

## 4. 归档到飞书

```bash
python3 "$S/upload_to_feishu.py" "$W/note.md" --folder "<文件夹链接或token>"
python3 "$S/upload_to_feishu.py" "$W/note.md"       # 用上次记录的默认文件夹
python3 "$S/upload_to_feishu.py" "$W/note.md" --update "<文档链接>"   # 更新已有文档（整篇覆盖）
python3 "$S/upload_to_feishu.py" --show-folder      # 查看默认文件夹
```

笔记修订后同步飞书时，用 `--update <文档链接>` 原地覆盖更新（保持文档链接不变；自动去除
正文首行主标题；注意会丢弃该文档内的评论与图片，仅用于纯文本笔记）。

调整已有文档的标题（文档标题与知识库节点标题会同步）：
`lark-cli drive +update-title --url "<文档链接>" --title "<书名>" --as user`。

**文件夹协议**：

1. 用户本次明确给了文件夹（链接/token）→ 直接用它上传（脚本自动记为默认）；
2. 用户没给 → 查默认（`--show-folder`）：有默认就用默认，并在最终回复里写明实际存到了哪里；
3. 没有再向用户索要，不要自己猜一个位置。

支持的文件夹形式：云空间目录链接（`.../folder/xxx`）、知识库链接（`.../wiki/xxx`）、
裸 token、"我的空间"根目录（`.../drive/my`）。
上传固定以用户身份创建（脚本已固定 `--as user`），文档出现在目标文件夹中。

## 5. 交付

最终回复包含：

- 飞书文档链接（上传成功时脚本返回的 URL）；
- 结构摘要：类型、节数、大致字数；
- 本地留档路径（`note.md` 及其 `parts/` 目录）。

## 依赖与环境

- `python3`（脚本纯标准库）。
- `lark-cli` 已安装且登录：先 `lark-cli auth status` 检查；失效时转 `lark-shared` 技能重新登录。
- 网络可用（创建飞书文档需要联网）。

## 边界

- 一次一本书；换书重新开单（新工作目录，不复用旧 parts）。
- 笔记是理解性内容（简介、分析、提炼），不是原文摘录或逐字复制。
- 冷门书籍信息有限时：写能确证的内容，把握不准处明确标注让用户核对，不编造。
- 用户可能在生成完成前补充要求（如"重点写某章"）：先完成当前节，再在后续节中融入；
  与结构规范冲突的需求（如"去掉层级"）先与用户确认再执行。
