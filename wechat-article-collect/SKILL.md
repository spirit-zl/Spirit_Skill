# 微信公众号文章采集

**表格驱动**的文章补全器：你在多维表格里粘链接，它把每行的标题、日期、正文、精华补齐。

与 `wechat-data` 的分工：那个是「给链接清单 → 批量下载归档 → 建表落库」；
这个是「表里已经有链接了 → 只补空缺的列」。抓取方式也不同 —— 本技能**直接抓
`mp.weixin.qq.com` 页面**，不依赖第三方下载服务（那个服务不稳定，见「排障」）。

## 什么时候用

- 「我表里填了文章链接，帮我补上标题/日期/正文/摘要」
- 「这个公众号的文章我都粘到多维表格了，跑一下」
- 「新加了几行链接，只处理新的，别重复跑」
- 「还是上次那个表，再跑一遍」（技能会先回显上次的文档名+链接让你确认）

## 三步走（必须按这个顺序）

### 第 0 步：先确认用哪个文档（不要跳过）

技能会记住**最近一次用过的文档**。每次开跑前先读出来：

```bash
C=~/.workbuddy/skills/wechat-article-collect/scripts/collect.py
python3 "$C" last --json
```

- 有记录 → **必须用 `AskUserQuestion` 问一次**，把「文档名称 + 文档链接」原样给用户看：

  > 上次用的文档是《六语先生》https://my.feishu.cn/wiki/FrbAwNqlliZK5fkdbBKc3raMnkd，
  > 这次还是用它吗？

  选项给两个：**继续用这个文档** / **换一个（我提供链接）**。
  - 继续 → 下一步用 `run --confirm-last`
  - 换 → 等用户给新链接，用 `run --base "<新链接>"`，记住的文档会自动更新

- 没有记录（首次使用）→ 直接问用户要多维表格链接。

> **不许自动沿用**：即使用户这次没说换文档、即使链接看起来一模一样，也要问。
> `run` 不带 `--base` 时会以退出码 3 停下并把文档信息打印出来，就是为了逼出这一步确认。

### 第 1 步：采集

```bash
python3 "$C" run --confirm-last                                  # 沿用上次的文档
python3 "$C" run --base "https://my.feishu.cn/wiki/xxxx"          # 用新文档（会更新记忆）
```

- `--base` 传**多维表格链接**（wiki 或 base 链接都行）或 `base_token`。
- 默认取该 Base 里**记录最多**的那张表；要指定用 `--table 表名`。
- 只处理「有链接、但标题或正文为空」的行。**已提取过的自动跳过**，不会重抓。
- **同一链接重复粘贴**（表里两行指向同一篇）：直接复用已提取的那行，标题/日期/正文/精华都搬过来，
  标记 `↺ 复用`，不重新下载、也不用你重写精华。
- `--force` 已有内容也重抓；`--limit 3` 先试水；`--delay` 调整间隔（默认 1.5 秒）。
- 结果写进会话目录的 `pending.json`，终端会打印成功/失败清单。

### 第 2 步：写精华，再写回

`run` 不会自己编精华 —— 那一步必须由你（模型）读正文来写。

1. 打开 `pending.json`，逐篇读 `文章正文`（每篇 2000–5000 字）。
2. 写 `summaries.json` 到同一目录：

```json
{"records": {"<record_id>": "这一篇的精华，200 汉字以内"}}
```

3. 写回：

```bash
python3 "$C" write          # 默认读最近一次会话
python3 "$C" write --force  # 已写回过的批次也要重写
```

`write` 会：补齐缺失的列 → 按 record_id 批量更新 → 把「已写回」时间记进 `pending.json`。

> 全是 `↺ 复用` 的批次可以跳过第 2 步的写精华：`write` 会直接取表里已有的精华填进去。

### 第 3 步：汇报

按用户偏好用表格给结果：`发表日期 | 文章标题 | 正文字数 | 精华字数`，并说明本次**新增几篇**、
**跳过几篇**、**复用几篇**、有没有失败（失败要给出链接和原因，不要笼统说"部分失败"）。

## 精华怎么写

用户的口径是**不超过 200 个汉字**（脚本按汉字个数校验，超了自动截断并提示）。

- 写**观点和结论**，不写「本文介绍了」这类空话，不写「作者认为本文…」的套话。
- 保留原文的关键判断、分点结构、可执行建议；数字和例证只在支撑观点时保留。
- 不虚构：原文没有的数字、人名、出处一律不写。
- 长度 130–180 汉字最舒服，别为凑满 200 硬加。

例：

> 作者认为家庭走下坡路的根因不是赚得少，而是三种习惯：把未来收入当现在的钱花、
> 自己不懂却想靠一次投资翻身、为面子超支。建议先立财务底线，每月留出一部分钱，
> 能全款再买、分期先算清还款压力；大额投资前先问自己懂不懂、亏多少、会不会影响
> 家庭生活；不拿存款换别人的评价。真正的底气是遇事有选择余地。

## 四个列（缺就补，有就沿用）

| 列名 | 类型 | 内容 |
|---|---|---|
| `文章链接` | 文本(url) | 用户自己填的，本技能只读不写 |
| `文章标题` | 文本 | `og:title`，公众号正文里重复的标题行会被去掉 |
| `发表日期` | 日期（`yyyy-MM-dd`） | 页面里的 `ct` 时间戳，按北京时间折算 |
| `文章正文` | 文本 | 正文区纯文本，图片留 `【图】` 占位 |
| `文章精华` | 文本 | 上一步写的 200 字摘要 |

**列名是契约**，已有同名列一律沿用它的类型，不覆盖。整表列顺序可以随便调。

## 抓取与清洗怎么做的

- 抓取用微信内置浏览器 UA 直连，单篇失败重试 2 次，再失败就记进 `failed[]` 不影响其他篇。
- 正文取 `#js_content` 容器（正确配对嵌套 div），剔除公众号名片、视频号卡片、脚本样式。
- 清洗两级：
  1. **尾部截断** —— 只在正文后半段找「加微信」「识别二维码」「—END—」「往期推荐」等标记，命中即砍掉后面全部；
  2. **逐行过滤** —— 开头「点击上方蓝字关注」、结尾「分享点赞在看」这类整行删掉。
- 具体规则在 `scripts/wxarticle.py` 的 `NOISE_LINE_PATTERNS` / `TAIL_CUT_PATTERNS`，
  换一个公众号如果还有残留广告，改这两个列表即可，不用动解析逻辑。
- 原页 HTML 归档到 `~/.workbuddy/data/wechat-article-collect/公众号下载/<公众号>/[YYYYMMDD]标题.html`，
  重采同名覆盖（幂等）。不想归档加 `--no-archive`。

## 排障

| 现象 | 原因与处理 |
|---|---|
| `页面里没有正文容器` | 链接可能是视频/图片消息，或已失效；确认能在浏览器打开 |
| `微信要求人机验证` | 抓得太快被风控；停几分钟，把 `--delay` 调大到 3–5 秒，单批少抓几条 |
| `文章已被发布者删除` / `因违规被屏蔽` | 链接本身废了，表里换一条或手工补 |
| 正文里还有广告 | 改 `NOISE_LINE_PATTERNS`（逐行删）或 `TAIL_CUT_PATTERNS`（从该行起截断） |
| `not_found` 写回失败 | 刚建完列就写会偶发；脚本已自带退避重试，仍失败就再跑一次 `write` |
| `lark-cli` 报权限/登录 | 用 `lark-shared` 技能处理授权，写用户云空间必须 `--as user` |

**不要再走的路**：`download-mcp` 的 `wechat` 工具（`changfengbox.top`）2026-10 起
`tools/call` 返回空 `result`，全批失败；`wechat_collection` 合集工具是服务端代理故障。
本技能已改成直连抓取，与这两个服务解耦。`wechat-data` 里的 `collect.py` 依赖它，
现在只适合解析**已下载的**产物目录。

## 其他命令

```bash
python3 "$C" last            # 上次用的文档：名称 + 链接 + 表名 + 使用时间
python3 "$C" last --json     # 同上，给程序判断用（无记录时返回 target: null）
python3 "$C" status          # 上次采集了哪些、写回没有、哪几篇失败
python3 "$C" write --dry-run # 只报告会更新几条，不写入
```

会话目录：`~/.workbuddy/data/wechat-article-collect/sessions/<base_token>_<table_id>/`，
里面 `pending.json`（待写/已写状态）、`summaries.json`（精华）、`done.json`（写回清单）、
`payload_*.json`（分批写入的中间文件，可删）。换数据根用 `WXAC_HOME`。

**记住的文档**存在 `~/.workbuddy/data/wechat-article-collect/config.json`：

```json
{"last": {"target": {
  "doc_title": "六语先生",
  "doc_url": "https://my.feishu.cn/wiki/FrbAwNqlliZK5fkdbBKc3raMnkd",
  "base_token": "QjCrb3QzkaBRn9sUF4LcciqmnzQ",
  "table_id": "tblDmfMmloX63QgV",
  "table_title": "数据表",
  "records": 8,
  "used_at": "2026-10-19 15:15:52"
}}}
```

每次 `run` 成功后自动刷新（`doc_url` 记的是用户当初给的那条链接，方便原样回显）。
用户说「换回上一个文档」时，直接读 `doc_url` 传给 `--base` 即可；想彻底清空就删这个文件。

## 合规

只采集用户有权获取的公开内容；控制频率（默认两篇间隔 1.5 秒，别改成 0）；
不虚构字段，抓不到的日期/标题留空并在结果里报告，不要猜。
