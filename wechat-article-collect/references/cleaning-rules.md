# 正文清洗规则说明

正文清洗是这套技能里唯一"需要按公众号调"的部分。解析（标题、日期、正文容器）
是结构化的，基本不会错；广告和自我介绍长什么样，每个号都不一样。

所有规则集中在 `scripts/wxarticle.py` 的两个列表里，改规则不用碰解析逻辑。

## 两级清洗

### 1. 尾部截断 `TAIL_CUT_PATTERNS`

公众号的广告区几乎都在正文末尾：加微信、二维码、往期推荐、"—END—"、课程入口。
命中其中任一行，**从该行起整段砍掉**。

为避免误伤正文里恰好出现的同款句子，只扫描正文**后半段**（从 50% 位置开始）：

```python
for idx in range(int(n * 0.5), n):
    if any(p.search(lines[idx]) for p in _TAIL_RE):
        cut_at = idx
        break
```

所以「加微信」若是文章正文里的正常讨论（比如讲私域运营的文章），前半段出现不会被砍，
后半段出现就可能被误砍 —— 这类文章请在 `TAIL_CUT_PATTERNS` 里把规则写得更具体，
例如 `^加微信[：:]?\s*[a-zA-Z0-9_-]+$`。

### 2. 逐行过滤 `NOISE_LINE_PATTERNS`

残留在正文中间的引导语（开头的"点击上方蓝字关注"、文末的"点个在看"）逐行删掉。
这里都是**整行匹配**（`^...$`），不会删掉句中的半句话。

## 常见噪声与对应规则

| 噪声原文 | 规则 |
|---|---|
| 点击上方蓝字关注我们 | `^点击上方.{0,12}关注` |
| 长按识别二维码关注 | `^(长按\|扫描\|扫码\|识别).{0,10}(二维码\|图片)` |
| （或加微信 asst555） | `^[（(]?或加微信` |
| 如添加频繁请加备用微信 | `^如添加频繁` |
| —END— | `^[—\-–]{0,3}(END\|end\|全文完)[—\-–]{0,3}$` |
| 预览时标签不可点 / 不喜欢 / 知道了 | 单行精确匹配 |
| 微信扫一扫 / 关注该公众号 / 使用小程序 | 单行精确匹配 |
| 免责声明：本文… | `^(免责声明\|版权声明\|特别声明)[：:]` |
| 往期推荐 / 推荐阅读 | `^(往期\|推荐\|精选)(文章\|阅读\|推荐\|内容)` |
| 分享 / 点赞 / 在看 / 收藏（独立成行） | `^\s*(分享\|点赞\|在看\|收藏)\s*$` |

## 加规则的正确姿势

1. 先跑一遍，把清洗后的正文**末尾 5 行**和**开头 3 行**打出来看（`collect.py run` 已打印摘要，
   要看全文读 `pending.json`）。
2. 找出残留的广告行，判断它是"整行该删"还是"后面全是广告"：
   - 整行删 → 加进 `NOISE_LINE_PATTERNS`
   - 后面全是广告 → 加进 `TAIL_CUT_PATTERNS`
3. 规则**尽量具体**，别用 `.*广告.*` 这种宽泛写法 —— 讲营销的文章正文会被整段删掉。
4. 改完用同一批链接跑 `run --force`，对比前后字数：正常只掉 5%–15%；
   掉一半以上说明规则太宽。

## 不会自动处理的情况

- **图片型文章**：正文全是图片（`【图】` 占位），清洗后字数很短。脚本会报
  "正文清洗后几乎为空"并计入失败，需要人工判断是否值得入库。
- **付费/被截断文章**：页面只给试读部分，抓到的就是这么多，脚本不会补。
- **多图文推送**：一次推送里的第二、三条有自己的链接，需要各自一行。

## 日期取不到时

`发表日期` 依次尝试：`#publish_time` 文本 → `var publish_time` → `var ct` 时间戳（北京时间）。
三个都没有就留空，并在 `failed[]` 之外单独体现（`pending.json` 里该行 `发表日期` 为 `""`）。
**不要猜日期** —— 宁可空着，也不要写一个看起来合理的值。
