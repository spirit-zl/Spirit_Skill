# 多文档合并进飞书

一串资料（一场培训的 8 个讲义、一个项目的 5 份记录、一套书的若干章节）→ 一篇结构统一的飞书文档。
每份文件的**文件名成为一级标题**，文件内部原有的标题整体下沉一级（H1→H2、H2→H3…）。

## 什么时候用

- 「把这几个 word/PDF 合成一篇飞书文档」
- 「这些讲义按顺序拼起来，放到我那个文件夹里」
- 「合并成一个文档，覆盖到 XX 这篇里」
- 「一本书拆成好几章了，帮我串成一篇」

## 交互顺序（用户定的，不许颠倒）

**第一步只问文件，不许顺带问链接。** 第二步拿到文件后才问链接。

### 第 1 步：要文件

用户触发时如果消息里没有文件/路径，只回一句：

> 把要合并的文档发我（Word / PDF / Markdown / TXT / EPUB 都行，多个可以直接一起拖），
> 也可以给我一个装着这些文件的文件夹路径。

- 用户拖进来的附件会有本地路径，直接拿来用。
- **不要**在这一步提飞书链接的事。

### 第 2 步：解析 + 报清单

```bash
S=~/.workbuddy/skills/doc-merge-to-feishu/scripts/run.sh
bash "$S" prepare <文件或目录...>
```

`prepare` 会：按**文件名自然排序**（`第2讲` 排在 `第10讲` 前面）→ 逐个转 Markdown → 图片抽到
会话目录的 `assets/` → 拼成 `merged.md`，并打印每个文件字数/标题数/图片数和警告。

> 给的是**目录**时，该目录下所有支持的文档都会被收进来（README、索引页也算）。
> 不想合并某个文件，就指名要给的那几个文件，别直接丢目录。

拿到结果后**先向用户交代三件事**，再问链接：

1. 一共合并了几个文件、多少字；
2. 有哪些文件没解析好（⚠ 行）——扫描版 PDF、没标题的 Word 都要点名，别含糊；
3. **建议的文档标题**（见下节），问一句「这个名字行吗，要改告诉我」。

### 第 3 步：要链接

> 给个飞书链接：给**文件夹**链接我就在里面新建一篇，给**某篇文档**链接我就把内容写进那篇（文档名不动）。

拿到链接后：

```bash
bash "$S" push "<飞书链接>"
```

- `push` 自己判断链接类型：文件夹 → 新建；文档 → 整篇覆盖。
- 退出码 **3** 表示要用户点头（目标文档已有内容 / 文件夹里已有同名文档），
  按下面的「需要确认的两种情况」处理，别自己加 `--force` 糊过去。
- 退出码 **4** 表示链接不是文档也不是文件夹（多维表格、电子表格、幻灯片等），
  原样告诉用户，让他重新给。

### 第 4 步：汇报

给出：文档标题、可点击链接、字数 / 图片数 / 来源文件数。顺带说一句本地也留了一份
`~/.workbuddy/data/doc-merge-to-feishu/sessions/<时间戳>/merged.md`。别复述全文。

## 逐篇写入（一篇一写，用户偏好）

用户说过「读一篇就写一篇，再读下一篇」时，**不要**用 `prepare` + `push`（那是攒成一整块再推），
改用 `stream`：

```bash
bash "$S" stream "<飞书链接>" <文件1> <文件2> ...
```

它按文件名自然排序，逐个「解析 → 立刻写入飞书」：

- 第 1 篇：链接是文件夹就新建文档，链接是文档就整篇覆盖（不需要再问一次，用户已明确要重写）；
- 第 2 篇起：追加到同一篇文档末尾（`docs +update --command append`）；
- 某一篇解析或写入失败不影响已经写进去的部分，最后汇总「已写入 N/M 篇」和失败原因。

好处是大文档不必攒成几十 KB 一次性推、也不怕中途限流把整次操作作废。
限流频繁时加 `--delay 2`（每篇之间等 2 秒）。

`stream` 也支持 `prepare` 的那些开关（`--no-images`、`--max-pages`、`--no-ocr`、`--title` 等）。

## 标题怎么定

脚本会按文件名给一个兜底标题（例如 `第1–5讲 合集`），**那只是兜底**。你要用文件名里的实际主题
替它起一个，规则：

- 只使用文件名里出现过的词，不许自己发挥出「进阶」「实战」「全集」这种原文没有的定位；
- 控制在 30 字内，不写书名号；
- 一份材料内部有明显递进关系时，可以用「从 A 到 B」这类结构，但 A、B 必须是文件名里的词。

例：`第01讲 商业模式` … `第05讲 渠道策略` → **商业模式与渠道策略（第01–05讲）**
（不要写成「一堂商业课全集」——原文没这个说法。）

确认后这样传：

```bash
bash "$S" prepare <文件...> --title "定好的标题"
# 已经 prepare 过就直接改：
bash "$S" push "<链接>" --title "定好的标题"
```

## 需要确认的两种情况

`push` 返回 `status: need_confirm` 时，把 JSON 里的信息翻成人话问用户，得到答复再重跑：

| reason | 情况 | 用户同意后 |
|---|---|---|
| `doc_not_empty` | 目标文档已有 N 字内容，覆盖会整篇替换 | 加 `--force` 重跑 |
| `folder_has_same_name` | 文件夹里已经有同名文档 | 覆盖它：加 `--update-existing`；另起一篇：加 `--title "新名字"` |

覆盖是**不可逆**的（飞书有历史版本，但别指望用户会去翻），所以必须问。

## 命令速查

```bash
S=~/.workbuddy/skills/doc-merge-to-feishu/scripts/run.sh

bash "$S" prepare <文件或目录...>        # 合并，生成会话
bash "$S" prepare <...> --recursive      # 目录也收子目录
bash "$S" prepare <...> --no-images      # 不要图片（纯文字稿）
bash "$S" prepare <...> --max-pages 60    # 单个 PDF 只解析前 60 页
bash "$S" prepare <...> --no-ocr         # 扫描件不识别（只要图）
bash "$S" prepare <...> --ocr-headings   # 扫描件按行高猜标题
bash "$S" prepare <...> --ocr-dpi 300    # 识别精度更高、更慢（默认 200）
bash "$S" prepare <...> --ocr-keep-image # 识别后仍保留整页图片
bash "$S" prepare <...> --title "标题"   # 指定标题
bash "$S" prepare <...> --json           # 给程序读的结果

bash "$S" push "<链接>"                  # 写入
bash "$S" push "<链接>" --dry-run        # 只探测链接类型和标题，不写
bash "$S" push "<链接>" --force          # 允许覆盖非空文档
bash "$S" push "<链接>" --update-existing# 文件夹里同名就覆盖
bash "$S" push "<链接>" --session <id>   # 指定历史会话（默认最近一次）

bash "$S" show                           # 看最近一次合并了什么、写了没

# 逐篇转换 + 逐篇写入（一篇一写）
bash "$S" stream "<链接>" <文件或目录...>  # 按文件名顺序，解析一篇写一篇
bash "$S" stream "<链接>" <...> --delay 2  # 每篇之间等 2 秒，防限流
```

## 合并规则（脚本固化的行为）

| 规则 | 说明 |
|---|---|
| 顺序 | 按文件名自然排序，不是按传入顺序；`02` 在 `10` 前 |
| 一级标题 | 每个文件的文件名（去扩展名），原样使用；`xx.md.pdf` 这种二次导出的会连 `.md` 一起去掉 |
| 标题下沉 | 文件内最高一级标题对齐到 H1 后再整体 +1，因此正文标题从 H2 起，最深到 H6 |
| 重复标题 | 文件内第一个标题与文件名指的是同一件事时自动删掉（忽略序号、标点、`.md` 残留），避免 H1 下面又一行同名 H2（`--keep-duplicate-title` 可关） |
| 图片 | 抽到 `assets/` 后按原位插入，飞书里是真实图片不是链接 |
| 表格 | Word / PDF / EPUB / HTML 的表格转 Markdown 表格；PDF 用 `find_tables` 定位（线条 + 文本两种策略），表格区域从正文流里剔除，不会又出表格又出一遍文字 |
| 断句 | 段落按「行距 / 字号」判是否同一段（<1.9 视为换行），遇句末标点或明显段距才断开；**列表项被折成多行时接回该项**，不会出现「…很难」/「封。」这种从中间劈开的段落 |
| 代码块 | 围栏代码块整体保留，里面以 `#` 开头的行不会被当标题 |
| 不加工 | 不改写、不摘要、不删段落；只做格式转换和标题层级调整 |

## 各格式的解析方式与局限

| 格式 | 怎么解析 | 已知局限 |
|---|---|---|
| `.docx` | python-docx 读 body，标题取样式（Heading N / 标题 N）或 outlineLvl | 文本框、页眉页脚、批注不提取；`.doc`/`.wps` 要另存为 docx |
| `.pdf` | PyMuPDF 取文本碎片 → 按 y 聚行、按 x 拼回逻辑行 → 标题优先用内置书签，没有则按字号（大于正文 1.12 倍且 ≤40 字的短行）分档 → 表格单独重建为 GFM 表格 → **扫描页自动 OCR** | 字号统一的纯文字 PDF 识别不出标题；字号极度密集的设计稿仍可能误判；双栏排版只有版心间隙足够干净时才会自动分栏读 |
| `.md` | 原样保留，标题只做层级平移 | 本地图片会收进 assets；外链图片保持原样 |
| `.txt` | 按空行分段，块内断行按中英文规则拼接；首行若与文件名相同则去掉 | 纯文本没有标题层级，全篇是正文；编码自动识别（UTF-8 / GBK 等） |
| `.epub` | zip 解包 → container.xml → opf → spine 顺序 → XHTML 转 Markdown | 跳过 nav/cover 章节；不解析 epub 内置目录 |

页眉页脚（跨页重复出现的页边文字）和页码会自动去掉，这是 PDF 处理里唯一会「删东西」的地方。

## 扫描版 PDF（OCR）

整页是图、没有文字层的扫描件会**自动识别成文字**，不用额外开关。判断标准：一页里文字少于
100 字、图片覆盖半页以上。

- 引擎按可用性自动挑：**macOS Vision**（系统自带、离线、中文准确率最好，约 0.3 秒/页）→
  **tesseract**（要装 `chi_sim` 语言包才认中文）→ 飞书 OCR 接口（需应用申请
  `optical_char_recognition:image` 权限，一般用不了）。
- 识别成功后**不再保留整页图片**（否则文字和图片重复一遍），要留加 `--ocr-keep-image`。
- 段落按行距合并：正常行距归到同一段，遇到句号或明显段落间距才断开；数字被拆开的
  （`2 0 24`）会接回 `2024`。
- 默认**不猜标题**，整页都当正文。想让大字号行变成二级标题加 `--ocr-headings`
  （行高比中位数高 1.3 倍才算），可能误判，先拿 `ocr` 子命令看一眼再决定。
- 单份 PDF 默认最多识别 300 页（`--ocr-max-pages` 可调）；超过 8 页会打进度。
- 识别为空的那一页会保留原图，不会凭空丢内容。

先确认某份 PDF 能不能读出来（不建文档、不写飞书）：

```bash
bash "$S" ocr "某文件.pdf" --pages 1-3           # 看前 3 页的识别结果
bash "$S" ocr "某文件.pdf" --pages 5 --headings  # 看标题识别效果
bash "$S" ocr "某文件.pdf" --json                # 给程序读
```

如果用户说「扫出来的 PDF 转成文档」「这本扫描书要文字版」，就是这条路径。

## 坑

| 现象 | 原因与处理 |
|---|---|
| `找不到装好依赖的 Python` | 用 `$HOME/.workbuddy/binaries/python/envs/default/bin/pip install python-docx pymupdf beautifulsoup4 lxml` 装，或用 `DOCMERGE_PYTHON` 指定 |
| 合并后标题从 H3 起 | 原文档自身从 H1 开始且有多个层级，属正常；若整篇跳级看起来别扭，检查是否开了 `--keep-duplicate-title` |
| PDF 里编号和正文断开（「正文」「1.」「标题」各成一段） | 已按逻辑行重建修复；仍有个别断行的是原 PDF 文本块本身错位，属源文件问题 |
| PDF 长段落被误判成标题 | 标题判定要求 ≤40 字且不以句号/逗号结尾；字号层级过于密集的设计稿 PDF 仍可能误判，看 `prepare` 的标题数是否异常偏高 |
| 表格变成一行行文字 | 已修：PDF 表格用 `find_tables` 定位后重建为 GFM 表格，表格区域的文字碎片会从正文流剔除，不会重复。飞书 markdown 导入本身支持表格（实测能正确落成表格块） |
| 表格缺字、只剩零星单字 | 已修：表格认领改为按「行框 + 列框」的空间范围，不再按文字互含匹配（否则单字单元格如「稿」「取」会漏出去） |
| 句子从中间断开（「…很难」/「封。」） | 已修：列表项折行会接回该项。仍有断开的是原 PDF 文本块本身就断在那里，属源文件问题 |
| 双栏 PDF 两栏串行（标题被粘成「误区一…误区二…」） | 已加版心间隙检测：两侧在多行里同时有字、且中间一条竖带几乎无人跨过时，先读左栏再读右栏；混合版面（表格 + 双栏）可能识别不出，属已知局限 |
| 图片没进文档 | 检查 `prepare` 输出里的图片数；`.emf/.wmf/.tif` 飞书不支持，会被跳过 |
| 扫描件没出文字 | 是不是整页文字多于 100 字（那会被当文字页）？先跑 `ocr` 子命令确认引擎能读；Linux 上要装 tesseract 中文包 |
| OCR 出来断行乱 | 扫描歪斜/双栏排版，引擎按 y 坐标排序会串行；`--ocr-dpi 300` 能改善清晰度，双栏需要手工调 |
| OCR 太慢 | 页数多时属正常（约 0.3 秒/页），可 `--max-pages` 或 `--ocr-max-pages` 限量；`--no-ocr` 只要图 |
| 写入报 `unsafe file path` | `@file` 只认当前工作目录下的相对路径，脚本已把 cwd 切到会话目录，不要手动改 cwd |
| `push` 说找不到会话 | 先跑 `prepare`；跨天再跑时注意 `--session` |
| 飞书报权限/登录 | 用 `lark-shared` 技能处理授权；写用户空间必须 `--as user`（脚本已固定） |

## 数据放在哪

`~/.workbuddy/data/doc-merge-to-feishu/sessions/<时间戳>/`：
`merged.md`（成品）、`assets/`（图片）、`session.json`（文件清单、警告、写入记录）。
`last_session` 指向最近一次，`~/.workbuddy/data/doc-merge-to-feishu/` 可整体删除重来。
换根目录用 `DOCMERGE_HOME`。

## 合规

只处理用户自己提供、有权使用的文档；不把内容发到飞书以外的地方；覆盖已有文档前必须得到明确同意。
