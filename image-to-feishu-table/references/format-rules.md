# 转换细则与正反例

## 一、为什么是 Markdown 表

飞书文档里没有 Markdown 表格语法，但把 GFM 表格文本粘进飞书文档（含新建空白文档）时，飞书会自动解析成**原生普通表格**。所以「转成飞书普通表格」= 输出标准 GFM 表，不需要调 API、不需要建文档。

同理，粘贴纯文本 Markdown 时飞书会保留加粗、列表，但**会**把 `#` 开头的行识别成标题 —— 这正是本技能禁用标题语法的原因。

## 二、表头与分隔行

正例：

```
| 编号 | 类型 | 输入 | 通过标准 | 结果 | 问题定位 |
| --- | --- | --- | --- | --- | --- |
| T01 | 典型 | … | 含 X/Y/Z 三步，口径一致 |  |  |
```

反例（缺分隔行、或用 `---` 数量对不上列数）——飞书会当成纯文本，不出表格：

```
| 编号 | 类型 |
| T01 | 典型 |
```

## 三、彩色标签的降级

图里常见「典型 / 边界·残缺输入 / 易错对抗」「L1 触发层 …」「5分（非常合适）」这类带底色的小徽章，飞书普通表格没有该样式。

- 正例：`| 边界 / 残缺输入 | 信息不足时会追问而非瞎编 | … |`（标签原样写进单元格）
- 正例：`| 5分（非常合适） |` 作为表头单元格
- 反例：在单元格里写 `【标签】典型`、`● 典型`、`[典型]` —— 符号是自行添加的，原图没有
- 反例：把标签合并进说明文字（`典型：主干流程跑得通`）—— 改变了原表结构

## 四、空单元格

原图某列整列空白（例如待填的「结果」「问题定位」）：

- 正例：`| T01 | 典型 | … | 含 X/Y/Z 三步 |  |  |`
- 反例：`| T01 | 典型 | … | 含 X/Y/Z 三步 | 无 | 待填 |`

只有原图**明确印着** `—`、`/`、`N/A` 时才照抄。

## 五、合并单元格拆平

原图「层级」列合并了 3 行写「L1 触发层」：

- 正例：3 行各自重复 `L1 触发层`
- 反例：只在第一行写，后续行留空（粘进飞书后语义丢失）

## 六、单元格内的竖线

- 正例：`| 条款 \| 说明 \|` （转义）
- 反例：`| 条款 | 说明 |`（表格列数被撑破，后续整表错位）

## 七、多图拼接

长表被切成 2–3 张截图时：

1. 按截图顺序取行，第一张定表头，后续截图跳过重复表头。
2. 拼接处若第一行与上一张最后一行完全一致（重复行），只留一条。
3. 在说明里报总行列数，例如「表格 4 列 × 9 行（由 2 张截图拼接，已去重表头）」。

## 八、纯文字版面

正例：

```
**误区二：把「流程」当成「判断」**
很多所谓经验其实是「先做什么后做什么」。流程可以封装，但流程里的关键判断点必须单独抽出、写成条件分支。

**补充：什么经验绝对不要封装**
① 只在一个人身上成立的直觉；② 依赖未公开数据源的判断；③ 涉及人身安全且无二次校验的决策。
```

反例（用了标题层级）：

```
## 误区二：把「流程」当成「判断」
```

反例（自行提炼小标题）：原图没有「一、二、三」这类概括，自己加上去就属于加工。

## 九、并列卡片

四个等大卡片、每块都有「标题 + 一句定义 + 一句问题表现 + 一句修法」→ 字段一致时优先输出表格：

```
| 层级 | 该层关注点 | 问题表现 | 修法 |
| --- | --- | --- | --- |
| L1 触发层 | 该不该被调用（描述写得准不准） | 该用的没用、不该用的乱用 | 触发频率测试 |
```

字段不一致时（每块只有一段话）→ 加粗小标题 + 段落，不做表格。

## 十、常见误判

| 情况 | 正确处理 |
| --- | --- |
| 图里只有一段话带冒号分点 | 当列表处理，不强行做表 |
| 图里是流程图 / 架构图 | 按文字节点顺序转写，不加箭头描述，不编造连接关系 |
| 图里是代码 | 用三反引号包裹，标注语言；缩进照原样 |
| 图里中英混排且英文是术语 | 保持原大小写，不加翻译 |
| 图有水印、页码、页脚 | 跳过，不进正文 |
| 图里公式 | 用纯文本保留（`Δ ≥ 20%`、`≤`、`≥`），不改写成 Word 公式 |
