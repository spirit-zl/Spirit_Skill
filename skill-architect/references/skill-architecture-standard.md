# Skill 架构标准参考文档
> 来源：飞叔AI沉思录《我拆解了花叔自建的skill之后，发现了如何写好skill的真相》
> 用途：skill-architect 技能的审查标准依据

---

## 核心洞察：Skill 的本质是什么？

**Skill = 专业知识 + 对 AI 行为的精确控制 + 可复用的工作系统**

很多人写 Skill 的问题在于：把它当成了知识库，或者简单的提示词模板。但真正顶级的 Skill，本质上是一个可执行的程序——有输入、有输出、有检查点、有异常处理、有优先级规则。

---

## 一、花叔的 Skill 设计哲学

### 1. "AI 是实习生，不是专家"

花叔在 SKILL.md 开头就定义了角色：

> "你是一位用HTML工作的设计师，不是程序员。用户是你的manager..."

诀窍：给 AI 一个具体的身份和关系定位，而不是泛泛的"你是一个助手"。

### 2. "默认值是陷阱"

花叔花了大量篇幅定义反 AI slop 清单——因为 AI 的默认输出就是训练语料的"最大公约数"，平庸且没有品牌识别度。

诀窍：明确告诉 AI 不要做什么，比告诉它做什么更重要。

### 3. "流程即产品"

花叔把整个设计工作流拆解成：
- 10步标准流程（含4个检查点）
- 8阶段 Fallback 模式
- 5步品牌资产协议
- 异常处理表

诀窍：Skill 不是知识库，是可执行的程序。

## 二、Skill 写作的 5 层架构模型

```
┌─────────────────────────────────────────┐
│ Layer 5: 触发层 (Trigger)             │
│ → 什么时候加载这个 Skill？              │
├─────────────────────────────────────────┤
│ Layer 4: 角色层 (Persona)             │
│ → AI 应该扮演谁？和谁的关系是什么？   │
├─────────────────────────────────────────┤
│ Layer 3: 原则层 (Principles)          │
│ → 不可违反的核心规则（按优先级排序）   │
├─────────────────────────────────────────┤
│ Layer 2: 流程层 (Workflow)            │
│ → 具体怎么做？步骤、检查点、异常处理  │
├─────────────────────────────────────────┤
│ Layer 1: 资源层 (Assets)              │
│ → 组件、模板、参考文档、脚本工具      │
└─────────────────────────────────────────┘
```

## 三、逐层拆解标准

### Layer 5: 触发层 —— 精准识别场景

**审查标准：**
- description 中是否穷尽了触发词？
- 是否区分了主干触发词和边缘触发词？
- 是否明确了不适用场景？

**好的写法示例（花叔）：**
```
触发词：做原型、设计Demo、交互原型、HTML演示、动画Demo、
设计变体、hi-fi设计、UI mockup、prototype、设计探索、
做个HTML页面、做个可视化、app原型...
```

### Layer 4: 角色层 —— 定义身份和关系

**审查标准：**
- 是否给了 AI 一个具体的职业身份（不是"助手"）？
- 是否定义了与用户的权力关系（上下级/合作伙伴/顾问）？
- 是否明确了能力边界（不是什么都能做）？

**好的写法示例（花叔）：**
> "你是一位用HTML工作的设计师，不是程序员"
> "用户是你的manager，你产出深思熟虑、做工精良的设计作品"
> "根据任务 embody 对应领域的专家：动画师/UX设计师/幻灯片设计师/原型师"

**公式：** 身份 + 关系 + 能力边界 + 动态角色

### Layer 3: 原则层 —— 优先级排序

**审查标准：**
- 原则是否有编号和优先级？
- 每条原则是否配了触发条件（什么时候执行）？
- 每条原则是否配了反例（真实踩过的坑）？
- 是否用检查点强制暂停？

**花叔的反例写法（标准模板）：**
```
反例（2026-04-20 真实踩过的坑）：
- 用户："给大疆 Pocket 4 做发布动画"
- 我：凭记忆说"Pocket 4 还没发布，我们做概念 demo"
- 真相：Pocket 4 已在 4 天前发布
- 后果：返工1-2 小时
- 成本对比：WebSearch 10 秒 << 返工 2 小时
```

### Layer 2: 流程层 —— 可执行的程序

**审查标准：**
- 是否有明确的步骤编号？
- 每个步骤是否有明确的输入、输出、检查点？
- 是否有异常处理表（场景→触发条件→处理动作）？

**花叔的标准流程（10步）：**
```
1. 理解需求（含事实验证）
2. 探索资源 + 抽核心资产
3. 先答四问，再规划系统
4. 构建文件夹结构
5. Junior pass（assumptions + placeholders）
6. Full pass（填 placeholder，做 variations）
7. 验证（Playwright 截图）
8. 总结（极简，只说 caveats 和 next steps）
9. 导出视频（默认带 SFX + BGM）
10. 可选：专家评审
```

**异常处理表标准格式：**
| 场景 | 触发条件 | 处理动作 |
|------|----------|------------|
| 需求模糊 | 用户说"随便做个设计" | 设计方向顾问模式 |

### Layer 1: 资源层 —— 可复用的组件

**审查标准：**
- 是否有 assets/ 目录存放可复用组件？
- 是否有 references/ 目录存放参考文档？
- 是否有 scripts/ 目录存放工具脚本？

**花叔的资源组织：**
```
assets/ 可复用组件
├── ios_frame.jsx iPhone 设备框
├── animations.jsx 动画引擎
├── deck_stage.js 幻灯片组件
├── sfx/ 37个预制音效
└── showcases/ 24个预制样例

references/ 参考文档
├── workflow.md 工作流程
├── design-styles.md 20种设计哲学
├── animation-pitfalls.md 14条动画避坑
└── ...

scripts/ 工具脚本
├── render-video.js 视频渲染
├── export_deck_pptx.mjs PPT导出
└── verify.py 验证脚本
```

## 四、快速转化需求的 7 步法则

### Step 1: 定义"领域边界"
- 这个 Skill 解决什么问题？
- 什么问题它不解决？（明确排除）
- 用户通常在什么场景下需要它？

### Step 2: 给 AI 一个"职业身份"
公式：**身份 + 关系 + 能力边界 + 动态角色**

### Step 3: 提炼"核心原则"
- 回顾做这个任务时最常犯的错误
- 回顾用户最常不满意的地方
- 把这些变成"原则 + 反例"

### Step 4: 设计"工作流程"
- 每个步骤要有明确的输入、输出、检查点
- 避免模糊描述，用具体动作

### Step 5: 预设"异常处理"
必须回答的问题：
- 需求模糊时怎么办？
- 技术难题时怎么办？
- 用户反馈不好时怎么办？
- 超出能力范围时怎么办？

### Step 6: 准备"资源库"
| 类别 | 内容 | 例子 |
|------|------|------|
| 组件 | 可复用的代码片段 | React组件、Python函数、CSS类 |
| 模板 | 标准化的文档格式 | 报告模板、邮件模板、代码模板 |
| 参考 | 知识库和最佳实践 | 设计规范、编码规范、FAQ |
| 工具 | 自动化脚本 | 渲染脚本、验证脚本、导出脚本 |

### Step 7: 写"触发词"和"描述"
描述（description）要包含：
- 能力概述（一句话）
- 触发词列表（穷尽）
- 主干能力（3-5个核心功能）
- Fallback 机制（需求模糊时怎么办）
- 可选功能（交付后的增值服务）

## 五、Skill 质量评分标准

| 层级 | 检查项 | 分值 |
|------|--------|------|
| Layer 5 触发层 | 触发词是否穷尽？是否有不适用场景？ | 20分 |
| Layer 4 角色层 | 是否有具体职业身份？是否明确关系+边界？ | 20分 |
| Layer 3 原则层 | 是否有编号+优先级？是否有反例？ | 20分 |
| Layer 2 流程层 | 是否有步骤+检查点+异常处理表？ | 25分 |
| Layer 1 资源层 | 是否有assets/references/scripts分类？ | 15分 |

**总分 100 分，80 分以上为高质量 Skill。**

## 六、好的 Skill 的心法

> 好的 Skill 不是"告诉 AI 做什么"，而是"构建一个让 AI 无法做错的系统"。

四个底层能力（花叔的秘密武器）：
1. **领域深度**：不是"懂一点"，而是深入理解
2. **对 AI 弱点的认知**：知道 AI 会凭记忆断言、产出 slop、闷头做到底
3. **迭代思维**：有版本历史，每个版本基于真实踩坑升级
4. **量化思维**：用数字让原则可执行
