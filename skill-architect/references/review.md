# 审查模式

> **来源**：由 SKILL.md「模式路由」判定为审查模式后加载，不可单独使用。
> **输入**：用户提供的 SKILL.md 路径（缺失时按主文件异常表追问）。
> **输出**：审查报告（首行必须是总分）+ A/B/C 三选一，等待用户选择。
> **返回**：用户选定后回到 SKILL.md 执行，不重新做模式判断。
>
> **继承**：主文件的身份、四类边界、原则 0–7 在本模式下全部适用，此处不重复。
> **偏移**：
> - 原则 2 收紧 —— 被审对象出现口号式原则（无场景、无后果）直接判不合格，Layer 3 每处 -2，不接受「反例待补充」。
> - 原则 6 收紧 —— 报告首行必须是总分，缺总分视为未完成。
> - 权限维持只读 —— 全程不写、不改、不删任何文件。

---

## 步骤1：读取标准 + 读取目标 Skill

**必须读取的文件：**
1. `references/standard.md` —— 审查标准
2. 用户提供的 SKILL.md 文件路径 —— 待审查 Skill

**读取后暂停，向用户确认：**
```
已读取你的 Skill：[Skill 名称]

正在按五层架构审查...
```

## 步骤2：逐层审查并评分

按五层架构逐层检查，每层给出：
- ✅ 做得好的地方
- ⚠️ 问题（含具体行号/位置）
- 💡 改进建议（可直接执行的修改方案）

**评分标准（总分100）：**

| 层级 | 检查项 | 分值 |
|------|--------|------|
| Layer 5 触发层 | 触发词是否穷尽？是否有不适用场景？ | 20分 |
| Layer 4 角色层 | 是否有具体职业身份？是否明确关系+边界？ | 20分 |
| Layer 3 原则层 | 是否有编号+优先级？是否有反例？ | 20分 |
| Layer 2 流程层 | 是否有步骤+检查点+异常处理表？ | 25分 |
| Layer 1 资源层 | 是否有 assets/references/scripts 分类？ | 15分 |

## 步骤3：输出审查报告（必须用户确认）

**报告格式：**
```
## Skill 审查报告：[Skill 名称]

### 总分：XX/100（[等级]）

等级标准：
- 90+ 优秀（可直接使用，有小幅优化空间）
- 80-89 良好（核心结构完整，部分层需加强）
- 60-79 及格（有基本框架，多个层有明显问题）
- <60 需重构（核心层缺失，建议按五层架构重建）

### 逐层审查结果

**Layer 5 触发层（XX/20）**
✅ [做得好的]
⚠️ [问题]
💡 [改进建议]

**Layer 4 角色层（XX/20）**
...

**Layer 3 原则层（XX/20）**
...

**Layer 2 流程层（XX/25）**
...

**Layer 1 资源层（XX/15）**
...

### 优先改进建议（按影响排序）

1. [最高优先级问题 + 具体修改方案]
2. ...
3. ...

---
请确认：
A. 按建议直接修改 SKILL.md 并输出完整文件
B. 我只想改某几层（请指定）
C. 先不改，我自己想想
```

**⚠️ 检查点：必须等用户选择后再行动，禁止直接修改文件。**

## 步骤4：按用户确认的方案修改

- 若选 A：按优先级逐层修改，每改完一层汇报，全部完成后输出完整 SKILL.md
- 若选 B：只改指定层，其他层保持不变
- 若选 C：结束，不修改文件

---

## 异常处理

| 场景 | 触发条件 | 处理动作 |
|------|----------|------------|
| 用户没有提供 SKILL.md 路径（审查模式） | 进入审查模式但未提供文件路径 | 询问文件路径，提供工作区技能列表供选择 |
| 用户提供的 SKILL.md 格式异常 | 文件无法解析或缺少核心字段 | 指出具体问题，建议按五层架构重建 |
| 用户在中途改变意图 | 审查→创建 或 创建→审查 | 重新执行模式判断流程 |
| 标准文档读取失败 | references/ 目录缺失或文件损坏 | 用内置五层架构知识继续工作，提示用户修复 references/ |
| 用户提供的 SKILL.md 路径不存在 | 文件路径错误或文件已被删除 | 提示路径错误，列出工作区现有技能供用户选择 |
| 用户要求用特定格式输出 | 用户说"用英文"、"直接写文件"、"只要评分不要建议"等 | 按用户要求调整输出格式，但检查点（暂停确认）规则不变 |
