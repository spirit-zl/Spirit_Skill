# 创建模式

> **来源**：由 SKILL.md「模式路由」判定为创建模式后加载，不可单独使用。
> **输入**：用户对目标 Skill 的需求描述（可能极简，按 7 步逐步补齐）。
> **输出**：SKILL.md 草稿正文 + A/B/C 三选一，等待用户选择。
> **返回**：用户选定后回到 SKILL.md 执行，不重新做模式判断。
>
> **继承**：主文件的身份、四类边界、原则 0–7 在本模式下全部适用，此处不重复。
> **偏移**：
> - 原则 2 放宽 —— 用户给不出真实反例时，允许写「反例待补充（YYYY-MM-DD）」占位，但须列入交付待补清单，禁止代为编造。
> - 原则 6 停用 —— 本模式没有可评分的对象，不得对用户需求打分。
> - 权限放宽 —— 步骤 9 用户明确选 A 之后解除只读，仅允许写入用户指定路径；在此之前禁止预写草稿。
> - 节奏放慢 —— 7 步逐段推进，每步独立等待确认，禁止连续输出多步。

## 状态锚点

每轮暂停后恢复时，先复述「当前在 步骤 N」，再继续。禁止跳步或倒回重走。

---

## 步骤1：确认领域边界

向用户询问并确认：

```
请描述这个 Skill 要解决的问题：
- 它解决什么问题？（一句话）
- 它不解决什么问题？（明确排除）
- 用户通常在什么场景下需要它？
```

**⚠️ 检查点：用户回答后，复述确认再进入下一步。**

## 步骤2：定义角色（身份+关系+边界）

引导用户明确：

```
这个 Skill 里，AI 应该扮演谁？
- 职业身份：（如：专利经纪人 / 抖音内容运营 / 数据分析师）
- 与用户的关系：（如：顾问 / 执行者 / 审核员）
- 能力边界：（如：能做X，不能做Y）
```

**角色公式**：`你是一位[具体职业身份]，不是[容易混淆的身份]。用户是你的[关系]。`

**⚠️ 检查点：输出角色定义草稿，等用户确认后再进入下一步。**

## 步骤3：提炼核心原则（含反例）

引导用户回顾：

```
这个领域里，最容易出错的地方是什么？
- 你做过类似任务时踩过什么坑？
- 用户最常在哪些方面不满意？
```

→ 把答案转化为格式：`编号 + 原则描述 + 触发条件 + 反例（场景/错误做法/后果/正确做法）`

**⚠️ 检查点：每条原则必须有反例，没有反例的原则删掉或问用户要真实案例。**

## 步骤4：设计工作流程（步骤+检查点+异常处理）

引导用户明确：

```
这个任务的标准流程是什么？
- 输入是什么？（用户提供的信息）
- 输出是什么？（交付物格式）
- 哪些步骤后需要暂停等用户确认？（检查点）
```

→ 写成编号步骤格式，每个关键步骤后标注 `**⚠️ 检查点：...**`

**⚠️ 检查点：流程草稿输出后，等用户确认再进入下一步。**

## 步骤5：补充异常处理表

必须回答的问题：

```
这些情况怎么处理？
- 需求模糊时 → 怎么处理？
- 信息不足时 → 怎么处理？
- 超出能力范围时 → 怎么处理？
- 用户不满意时 → 怎么处理？
- 用户提供的文件路径不存在时 → 怎么处理？
- 用户在中途改变意图时 → 怎么处理？
```

→ 写成表格：

| 场景 | 触发条件 | 处理动作 |
|------|----------|------------|
| [异常] | [什么时候发生] | [具体怎么做] |

**⚠️ 检查点：异常处理表输出后，等用户确认再进入下一步。**

## 步骤6：整理资源库

引导用户明确：

```
有没有可以复用的内容？
- 模板/话术库/规范文档 → 放 references/
- 可复用脚本 → 放 scripts/
- 组件/素材 → 放 assets/
```

→ 生成本地目录结构建议，问用户哪些资源已准备好。

**⚠️ 检查点：资源清单输出后，等用户确认再进入下一步。**

## 步骤7：编写触发词和描述

引导用户穷举：

```
用户会怎么描述这个需求？列出所有可能说法：
- 正式说法：（如：创建 Skill、写 Skill）
- 口语说法：（如：帮我做个技能、我想搞个 Skill）
- 相关关键词：（如：skill、技能、agent）
```

→ 收集阶段尽量穷举（帮用户想全）；但落进 description 时只留 3–5 个最高频表达，其余不必塞入。

**⚠️ 检查点：触发词列表输出后，等用户确认再生成草稿。**

## 步骤8：生成 SKILL.md 草稿

收集完7步信息后，**先读 `templates/SKILL-template.md`**，以它为唯一骨架生成完整内容（不直接写文件，只输出内容让用户审阅）。

**禁止在本文档里另写一份模板** —— 骨架只有 `templates/SKILL-template.md` 一处，本文只负责「哪一步填哪一节」。

**七步答案 → 模板章节对照：**

| 收集到的 | 填进模板的 |
|---|---|
| Step 1 领域边界 | `## 使用前提` 两行 + 角色行里的「不做【相邻职责】」 |
| Step 2 角色定义 | 标题下那三行（身份 / 关系 / 产出物） |
| Step 3 核心原则 | `## 核心原则`，每条按「命题 + 触发条件 + 判定 + 反例」展开 |
| Step 4 工作流程 | `### 标准流程`（步骤与检查点）+ `## 输出规格`（Step 4 问的输入/输出格式落这里） |
| Step 5 异常处理 | `### 异常处理` 表 |
| Step 6 资源库 | `## 资源库`，无文件的分类整节删除 |
| Step 7 触发词 | frontmatter 的 `description`（单行；3–5 个高频表达，不要穷举成长串） |

填完后逐项检查：所有【】已被替换、没内容的章节已删掉、`description` 仍是单行。

**⚠️ 检查点：草稿输出后，必须等用户确认，禁止直接写文件。**

## 步骤9：按用户反馈修改草稿

```
请确认：
A. 直接用，写入 SKILL.md 文件
B. 需要调整（请指出哪层/哪部分）
C. 先不输出，我想再想想
```

- 若选 A：将确认的 SKILL.md 内容写入用户指定路径
- 若选 B：只改指定部分，改完再次输出给用户确认
- 若选 C：结束，不写文件

**⚠️ 检查点：必须等用户明确选择 A 之后再写文件。**

## 步骤10：交付完成，输出使用建议

文件写入后，输出：
- Skill 文件路径
- 建议下一步：用本技能（skill-architect）审查一遍刚创建的 Skill，自检质量
- 触发词测试建议：用几个触发词测试 Skill 是否按预期加载

## 异常处理

| 场景 | 触发条件 | 处理动作 |
|------|----------|------------|
| 用户需求描述太模糊（创建模式） | 无法提取领域边界 | 用7步法则逐层引导，一次只问一步 |
| 用户在中途改变意图 | 审查→创建 或 创建→审查 | 重新执行模式判断流程 |
| 标准文档读取失败 | references/ 目录缺失或文件损坏 | 用内置五层架构知识继续工作，提示用户修复 references/ |
| 7步引导中用户某步说"不知道" | 创建模式下用户无法回答某步问题 | 提供3个示例引导思考，仍无法回答则跳过该步并在原则层标注"待用户补充" |
| 用户要求用特定格式输出 | 用户说"用英文"、"直接写文件"、"只要评分不要建议"等 | 按用户要求调整输出格式，但检查点（暂停确认）规则不变 |
